FundsXML → TPT V7.0: data-gap analysis & enrichment

Tripartite Template (Solvency II look-through) export · tpt_v7_export.xslt · FundsXML4.xsd (4.2.11)

1. Executive summary

The Tripartite Template (TPT) V7.0 is the FinDatEx/EFAMA industry standard insurers use to receive fund “look-through” holdings for Solvency II. Each fund/share class is described by a fixed list of 152 columns. tpt_v7_export.xslt reads positions from FundDynamicData/Portfolios/Portfolio, joins them to AssetMasterData/Asset by UniqueID, and emits one row per position per share class.

Key finding. The instrument-level data in the sample files is already complete (every bond carries coupon/maturity, every position joins to an asset, etc.). The only systematic gap is the fund-issuer / QRT portfolio block. None of the 274 sample files carry a FundStaticData/InvestmentCompany or Custodian, so the exporter could not fill the fund-issuer columns.

5. ShareClass/Portfolio variant (Task 2)

tpt_v7_export_shareclass.xslt reads the look-through positions from each share class's own SingleFund/ShareClasses/ShareClass/Portfolios/Portfolio instead of the fund-level FundDynamicData/Portfolios/Portfolio. NAV (col 5), valuation date (col 6) and cash ratio (col 9) are then taken per share class.

Expected behaviour confirmed. Single-share-class funds produce byte-identical output (the share-class portfolio is the fund portfolio). Multi-share-class funds diverge: the forward path repeats the fund NAV on every block, while the variant reports each share class's own NAV and holdings — the share-class NAVs sum back to the fund NAV. Per-block valuation weights reconcile to ~1.0 in both.

6. Reverse path: TPT7 node → CSV (Task 3)

FundsXML can also carry a TPT report natively, as a structured RegulatoryReportings/IndirectReporting/TripartiteTemplateSolvencyII_V7 node. build_tpt7_sample.py populates that node from a real example TPT file (ERSTE STOCK ENVIRONMENT, AT0000A2G6F2); the file is schema-valid, and tpt7_node_to_csv.xslt flattens it back to the 152-column CSV.

8. Documented heuristic limits

  • CIC category (col 12) and Underlying asset category (col 131): FundsXML AssetType cannot distinguish government vs corporate bonds, or listed vs unlisted equity — a best-effort mapping is used.
  • Identification format: the real TPT writes the codification type as 1.0; we emit 1. Same meaning (ISO 6166 / LEI).
  • Asset types FE (fee), RT, RI are present in the samples but are non-investment lines; they map to CIC category 0 (other).
